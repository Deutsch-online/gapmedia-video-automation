# حلقه — پنل خودکار مهمان برتر

اجرای محلی با Node.js نسخهٔ ۲۰ یا جدیدتر:

```sh
npm start
```

ویندوز: `START-WINDOWS.cmd`. برای نصب اتصال واقعی در ویندوز، `INSTALL-LIVE.cmd` را اجرا کنید. پنل: http://localhost:3210 ؛ خروجی شفاف: http://localhost:3210/overlay با اندازهٔ 1080×1920.

برای دریافت واقعی از تیک‌تاک ابتدا `npm install` اجرا کنید؛ بستهٔ اختیاری `tiktok-live-connector@2.5.0` نصب می‌شود. آزمایش و پنل به نصب هیچ بسته‌ای نیاز ندارند. سپس یوزرنیم میزبان را در پنل وارد و اتصال را بزنید. هیچ کلید یا سرویس پولی خودکار فعال نمی‌شود. دسترسی رایگان سرویس امضا و تیک‌تاک تضمین‌شده نیست. اتصال و دریافت رویداد زنده در این محیط تأیید نشده است.

## استفاده

1. مهمان‌ها را با یوزرنیم و در صورت امکان شناسهٔ عددی تیک‌تاک ثبت کنید. شناسه باید رشته باشد تا اعداد بلند تغییر نکنند. اگر شناسه ندارید، حضور مهمان در رویدادهای حساب مانند کامنت برای شناسایی لازم است.
2. از میز آزمایش، حالت آزمایشی را شروع کنید؛ گیفت‌های چند حامی به یک مهمان جمع می‌شوند. حلقه فقط به مهمان اول می‌رسد. در تساوی، برندهٔ قبلی حفظ می‌شود.
3. مختصات مرکز X و Y و قطر حلقه را برای هر مهمان مطابق صحنه تنظیم کنید. دوربین مهمان از LIVE Studio می‌آید؛ برنامه فقط حلقه و حامیان را نمایش می‌دهد. تغییر چیدمان مهمان‌ها در LIVE Studio نیازمند اصلاح مختصات است؛ تشخیص خودکار جای تصویر پیاده نشده است.
4. منبع Browser/Link را در نسخه‌های پشتیبانی‌شدهٔ LIVE Studio اضافه کنید. اگر در دسترس نیست از OBS Browser Source استفاده کنید. پس‌زمینه و مرکز حلقه شفاف‌اند. ثبت پنجرهٔ مرورگر به‌تنهایی شفافیت را حفظ نمی‌کند.
5. اتصال موفق واقعی داده‌های آزمایشی را پاک می‌کند. اتصال مجدد به همان حساب و همان اتاق، امتیازهای زنده را نگه می‌دارد؛ اتاق جدید از صفر شروع می‌شود. برای هر لایو جدید دکمهٔ صفرکردن را بزنید. تنظیمات و مهمان‌ها حفظ می‌شوند؛ امتیازهای جلسه پس از خاموش‌شدن برنامه از صفر شروع می‌شوند.

سطوح اولیه: ۱۰ ساده، ۱۰۰ درخشان، ۲۰۰ نقره‌ای، ۵۰۰ طلایی، ۱۰۰۰ یخی، ۲۰۰۱ آتش اژدهایی؛ قاب طلایی با شیر، یخی با اژدهای یخی، و آتشی با اژدهای آتشین تزئین شده است. تصاویر شفاف تولیدشده با هوش مصنوعی با هالهٔ ابری و ذرات متحرک ترکیب می‌شوند. حلقهٔ ساده سه طرح مداری، نقطه‌ای و دوحلقه‌ای دارد. حداقل‌ها قابل تغییرند.

## سازگاری با نمونهٔ گیت‌هاب

ساختار ورودی بر اساس بررسی `live-driving-quiz/guests.mjs`، `supporters.mjs` و `likes.mjs` در مخزن [Deutsch-online/gapmedia-video-automation](https://github.com/Deutsch-online/gapmedia-video-automation/tree/main/live-driving-quiz) تهیه شده است. فایل‌های پروژهٔ قبلی تغییر نکرده‌اند. UI جدید مستقل است.

برای اتصال برنامهٔ قبلی، «دریافت از رابط محلی» را فعال کنید و رویداد **خام** را از پردازشگر gift/like آن برنامه به `POST http://localhost:3210/api/events` با Content-Type برابر application/json بفرستید. این پل باید روی همان کامپیوتر اجرا شود؛ پل در مخزن قبلی هنوز نصب نشده است. نمونهٔ فرستادن از Node.js:

```js
async function forward(type, event) {
  const response = await fetch('http://localhost:3210/api/events', {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({...event, type})
  });
  if (!response.ok) throw new Error('Ring bridge rejected event');
}
// داخل پردازشگرهای موجود، با مدیریت خطا:
// forward('gift', data).catch(console.error);
// forward('like', data).catch(console.error);
```

فیلدهای gift: `type: 'gift'`، `user.id`، `user.nickname`، `common.msgId`، `common.createTime`، `giftId`، `diamondCount`، `repeatCount`، `receiverUserId`؛ نام گیفت و عکس اختیاری‌اند. گیرنده از `giftExtra.toUserId` یا `toUser.id` هم خوانده می‌شود. برای کمبو `giftDetails.giftType: 1` و `repeatEnd: true` در پایان لازم است. `groupId` از ثبت تکراری کمبو جلوگیری می‌کند. زمان باید در محدودهٔ دو دقیقهٔ اخیر باشد. شناسهٔ رویداد، فرستنده و گروه رشته باشند.

فیلدهای like: `type: 'like'`، `user.id`، `user.nickname`، `common.msgId`، `common.createTime`، `count` (افزایش لایک همان فرد). عدد `total` لایک اتاق در امتیاز کسی حساب نمی‌شود. لایک امتیاز گیفت مهمان را تغییر نمی‌دهد.

اگر گیرنده مشخص نباشد، گیفت در فعالیت حامیان نشان داده می‌شود اما امتیاز هیچ مهمان بالا نمی‌رود؛ شمارندهٔ تشخیص‌داده‌نشده افزایش می‌یابد. ارزش کوین نامشخص هم حساب نمی‌شود. هیچ امتیازی از قیمت پولی یا نام گیفت حدس زده نمی‌شود.

اجرای محلی روی loopback است. میزبانی آنلاین با PUBLIC_URL و RINGS_ADMIN_TOKEN انجام می‌شود؛ سرور بدون رمز خصوصی اجازهٔ تغییر تنظیمات نمی‌دهد. لینک مدیریت به شکل /?panel=1#TOKEN و خروجی عمومی /screen است. توکن از hash خوانده و در sessionStorage همان مرورگر نگهداری می‌شود؛ در آدرس درخواست‌ها یا دادهٔ عمومی قرار نمی‌گیرد. فایل deploy.py فقط میزبانی رایگان CPU-basic را می‌پذیرد. رمز مدیریت در خروجی رمزنگاری‌شدهٔ RSA تحویل می‌شود؛ کلید خصوصی در مخزن منتشر نمی‌شود. برنامه برای اتصال زنده نیازمند سرور Node است و وب‌سایت استاتیک نیست.

## بررسی

```sh
npm test
```

نمایش حامیان: گیفت‌دهنده‌ها در گروه بالایی با قاب درخشان؛ حداکثر ۱۰ لایک‌کننده در گروه پایین. نفر اول لایک تاج طلایی و نور ویژه دارد و با تغییر رتبه، تاج خودکار منتقل می‌شود. این رتبه‌بندی از رتبهٔ گیفت مهمان مستقل است.

غرش شیر و اژدها با Web Audio به شکل افکت صوتی طراحی می‌شود؛ ضبط واقعی حیوان نیست. کلید قطع و بلندی صدا در پنل است و هر قاب دکمهٔ آزمایش صدا دارد. غرش فقط هنگام تغییر مهمان برتر یا سطح طلایی/یخی/آتشی پخش می‌شود. برای بازشدن قفل صدای مرورگر، یک‌بار در صفحهٔ خروجی کلیک کنید؛ در OBS از Interact استفاده کنید.
